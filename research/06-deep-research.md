# Research result

**Status: Partial**

DuckDB 2.0.0 LTS “Cinnamon Teal,” released 2026-10-21, changes new-file storage compatibility, lambda syntax, and the default SQL parser, and each of those breaks has an official migration action. Agent skills should also plan for Quack and `CONNECT` (usable, but not a frozen protocol), for CLI output that changes shape when the process looks like an agent, and for asynchronous reads that turn on by themselves only for the formats October still lists. Where the August preview was broader—lambda removal already finished, an invisible parser swap, async I/O on the native file format and on writes—the October release deferred or narrowed the behavior.

### Storage format
New DuckDB 2.0.0 files use storage version 69, which versions before 2.0 cannot read—1.5.6 reports it can read only versions 64–68—while 2.0.0 can read and write older files without changing their storage version, so those files stay readable by the earlier version; create an older-format file with `-storage-version`, `storage_compatibility_version`, or `ATTACH STORAGE_VERSION`, or convert with `EXPORT DATABASE` on the old binary and `IMPORT DATABASE` on 2.0. [S1] Files created by v1.0 through v1.5, including 1.4 and 1.5, use storage version 64 by default, older releases can opt into a newer format, and the version table associates 67 with v1.4.x, 68 with v1.5.x, and 69 with v2.0.x; a v2.0.0-format file cannot be opened before v2.0.0, its header version field holds 999, and DuckDB 1.5.5 and earlier report 999 rather than 69. [S2]

### Lambdas, parser, and other breaks
The single-arrow form `x -> x + 1` is disabled by default in favor of `lambda x : x + 1`, and `SET lambda_syntax = 'enable_single_arrow'` is a temporary bridge that v2.1 will remove together with the single-arrow syntax; the August preview called that transition completed, but October treats it as the next step, not a finished removal. [S3] The PEG parser is the default and previously valid queries should still parse; roll back with `INSTALL AND LOAD legacy_parser` followed by `SET enable_legacy_parser = true`, which the August preview did not document when it said the swap should be unnoticeable and to file an issue. [S4] Integer `//` and `%` by zero now error instead of NULL—use `TRY(...)` or `SET error_on_division_by_zero=false`, while `1 / 0` still returns `inf`—`preserve_identifier_case` is a VARCHAR (`'preserve_case'` by default, `'lowercase'`, or `'uppercase'`) with `true`/`false` still mapped, S3 URL parameters are off by default so `?` and the following text are part of the object key (use secrets, or `SET s3_enable_deprecated_url_parameters=true` after loading httpfs), `custom_profiling_settings`, `enable_http_logging`, and `http_logging_output` were removed, `profiling_mode` is deprecated and ignored, and since v1.5.0 the CLI defaults to non-queryable `shell_log_storage` unless logging is enabled with storage `'memory'`. [S5]

### Quack, CONNECT, and serving
Quack uses the `quack:` scheme and default port 9494 over plain HTTP or HTTPS, serializes messages as `application/duckdb`, is client-initiated, and after the handshake uses one request–response per query, with large results streamed by follow-up FETCH requests. [S6] `CONNECT` and `DISCONNECT` were introduced in DuckDB 2.0: `CONNECT` routes the session to an attached database or a connection string so later queries run remotely, `DISCONNECT` returns to the local database and errors if none is active, and a non-DuckDB target must start with the database type, as in `CONNECT 'postgres:dbname=mydb host=localhost'`. [S7] `duckdb -serve` and `duckdb -connect`, added in 2.0, serve an in-memory database on localhost:9494 by calling `quack_serve` and run `CONNECT` to that server using the default quack secret, which `-serve` creates if missing; the optional form is `TYPE:SECRET`, and only the quack type can be served. [S8] The server binds only to localhost and does not use TLS for local URIs unless that is changed; non-local hostnames require `allow_other_hostname = true` and then default to HTTPS with a self-signed certificate, and beyond local-only use Quack should not be exposed directly—terminate TLS at an HTTP reverse proxy. [S9] This Quack is polished, with substantial performance and stability improvements, `CONNECT` can attach and switch to a remote database in one command, and `allow_other_hostname` (direct exposure) is only for testing. [S10] The Quack FAQ says the protocol is not yet stable, and expected breaking changes may include the protocol, function names, and default settings. [S11]

### CLI agent mode
Agent mode turns on automatically only when a known AI-agent environment variable such as `AI_AGENT` is set, standard output is not a terminal, and no output-mode flag such as `-csv` or `-json` was passed. [S12] `-agent` and `-no-agent` force it on or off, `DUCKDB_AGENT_MODE` set to `1` or `0` does the same, and the command-line flags take precedence over that variable. [S13] Results are compact Markdown tables with a footer of the row count and, when the whole result was read, an order-independent hash; up to 1,000 rows and 10,000 bytes are shown in full, a larger result shows the first and last rows with the total count, and cells truncate at 500 characters. [S14] `.maxrows`, `.maxbytes`, and `.maxcellwidth` adjust those limits, and `.startup_text none` as the first line of `~/.duckdbrc` hides the startup line that announces the mode. [S15] The CLI then replaces padded boxes, prints an explicit truncation notice, stops runaway queries early, reports errors as JSON, and reports expected cost before long-running SQL so the agent can decide whether to wait; TPC-H experiments cut the DuckDB output the model read by 59%, `-agent` turns the mode on for manual testing, and the agent should be instructed to turn it off with `-no-agent`. [S16]

### Asynchronous I/O
Asynchronous I/O applies to reading Parquet and CSV, CSV only for uncompressed, seekable, UTF-8 files, and it is used automatically for those formats, including through DuckLake, while JSON and DuckDB’s native database format use synchronous I/O. [S17] The August preview had also included DuckDB’s own file format, asynchronous Parquet writes, and MMAP and DIRECT_IO modes; October does not document those as part of asynchronous I/O. [S18][S19] Reads are controlled by `async_threads` (default four times the system thread count, capped at 256), `threads` for the worker pool, and `read_ahead_depth` (`-1` memory-bounded by default, a positive N caps jobs with no memory budget, `0` turns read-ahead off), along with `http_retries`, `http_retry_wait_ms`, `http_retry_backoff`, `http_client_pool_capacity` (automatic, tracks `async_threads`, capped at 256), and `memory_limit`; `fsync_mode` controls local write flushes, not async reads. [S20] The October 21 announcement does not tell an agent to set those options. [S21]
